# Fuel SK: карта цін на пальне + віджет + маршрут з економією

Проєкт за зразком репо `krmll4444/privat_currency`: cron на GitHub Actions збирає дані → JSON у репо → статичний фронтенд на GitHub Pages + віджет Scriptable на iPhone. Без сервера, без Apple Developer акаунта, безкоштовно.

## 1. Мета

- Збирати ціни на пальне на заправках у Словаччині (основне джерело: benzin.sk, далі додаткові).
- Показувати заправки з цінами на карті (PWA, відкривається з головного екрана iPhone).
- Віджет на iPhone (Scriptable): найдешевша заправка поруч / по дорозі.
- Прокладати маршрут A→B з урахуванням витрати пального та вигоди від заправки: чи варто робити обʼїзд заради дешевшої ціни.

## 2. Обмеження

- Немає платного Apple Developer акаунта: жодних нативних iOS-апок для розповсюдження. PWA + Scriptable.
- Є Mac (для розробки) та iPhone.
- Без власного сервера: усе на GitHub Actions + GitHub Pages.
- Країна: Словаччина. Валюта EUR, мова інтерфейсу: українська (з можливістю додати sk/en).
- Стек: Node.js (ESM, `.mjs`) для engine, чистий HTML/JS (без збірки, або мінімальний Vite) для PWA.

## 3. Архітектура

```
.github/workflows/   # cron: збір даних, комміт JSON, деплой Pages
engine/              # збирач: fetch, парсинг, нормалізація, геокодинг, злиття
data/
  stations.json      # актуальний знімок (станції + ціни)
  history.jsonl      # історія цін (по рядку на знімок або зміну)
  geocache.json      # кеш адреса -> координати
  advice.json        # легкий файл для віджета (топ станцій по регіонах)
pwa/                 # карта, список, маршрут, налаштування
widget/              # Scriptable JS
docs/
README.md
```

Потік: cron → `engine` тягне джерела → зводить у `stations.json` → комміт у репо → Pages віддає `pwa/` і `data/*.json` → PWA та віджет читають JSON з Pages.

## 4. Джерела даних

### 4.1 benzin.sk (основне)

Старий PHP-сайт, HTML на сервері, публічного API немає. Пошук працює звичайним GET.

Приклад запиту:

```
https://www.benzin.sk/index.php?price_search_town=Ko%9Aice&price_submit=Vyh%BEada%9D&price_search_region=3&price_search_brand=-1&price_search_fuel=4096&price_search_day=14&selected_id=118&article_id=-1
```

Параметри:

| Параметр | Значення |
|---|---|
| `price_search_town` | місто або вулиця (закодовано у windows-1250; занадто короткий рядок сайт відкидає) |
| `price_search_region` | номер краю зі списку (`3` = Košický). Точні номери взяти з `<select>` |
| `price_search_brand` | `-1` = будь-який бренд, інакше id бренду з `<select>` |
| `price_search_fuel` | код пального (`4096` = Natural95+). Схоже на біти. Решту кодів взяти з `<select>` |
| `price_search_day` | вікно актуальності (за 24 год / 7 / 14 / 30 / 60 / 90 днів) |
| `price_submit`, `selected_id=118`, `article_id=-1` | службові, залишати як є |

**Кодування (критично).** Параметри в URL і, імовірно, відповідь у **windows-1250**. `š` = `%9A`, `ľ` = `%BE`, `ť` = `%9D`.
- Відповідь декодувати через `new TextDecoder('windows-1250')`.
- Параметри кодувати через `iconv-lite` (`iconv.encode(str, 'win1250')` → percent-encode байтів), а не через `encodeURIComponent` (це UTF-8 і ламає діакритику).

Особливості за підказкою на сторінці:
- Клік по станції відкриває її деталь з цінами інших видів пального: повну ціну станції беремо зі сторінки станції (`pump_id`), а не зі списку.
- Іконка біля ціни означає «не старша 7 днів». Якщо ціна оновлювалась кілька разів за вибраний період, показується остання.
- Дані схожі на краудсорсні: зберігати `updatedAt` кожної ціни й показувати вік.
- Розділ «Siete ČS» (`selected_id=163`, параметри `network`, `kraj_id`, `okres_id`, `obec_id`, `brand_id`, `pump_id`) дає навігацію по мережах/областях. Використати для повного обходу, якщо порожній `price_search_town` не працює.
- Середні ціни за тиждень є на головній (блок «Priemerné ceny PHM … podľa Benzin.SK»): брати як базову ціну для формули економії (можна також рахувати власне середнє по знімку).

### 4.2 Додаткові джерела (у порядку пріоритету)

1. **OpenStreetMap / Overpass** (`amenity=fuel`, Slovakia): координати, бренд, назви. Використовувати як довідник станцій і для зіставлення з benzin.sk (за брендом + відстанню).
2. **Сторінки мереж** (Slovnaft, Shell, OMV, MOL, Orlen): якщо віддають ціни по станціях; часто лише загальні. Реалізувати як окремі модулі-адаптери; необовʼязково на першому етапі.
3. **Google Places `fuelOptions`**: перевірити, чи повертає дані для Словаччини; лише як опція.

Кожен адаптер повертає одну й ту саму нормалізовану структуру (див. розділ 5). Злиття: для однієї станції й виду пального береться свіжіша ціна, зберігаються `source` та `updatedAt`.

```json
      "lon": 21.2611,

      "prices": {
        "natural95": { "eur": 1.853, "updatedAt": "2026-09-28", "source": "benzin.sk" },
        "diesel":    { "eur": 1.996, "updatedAt": "2026-09-27", "source": "benzin.sk" },
        "lpg":       { "eur": 0.849, "updatedAt": "2026-09-20", "source": "benzin.sk" }
      }

```

Ключі пального: `diesel`, `diesel_plus`, `natural95`, `natural95_plus`, `natural98`, `natural99_plus`, `lpg`, `cng`, `adblue`.

`data/advice.json`: легка версія для віджета, наприклад топ-N найдешевших станцій на пальне по кожному краю + базова ціна + `generatedAt`. Не тягнути весь `history.jsonl`.

`data/history.jsonl`: по рядку на день (або на зміну ціни): `{ts, stationId, fuel, eur}`. Дописується кроном.

`data/geocache.json`: `{ "адреса нормалізована": {"lat":..,"lon":..,"source":"nominatim"} }`.

## 6. Engine (`engine/`)

Модулі:

- `sources/benzin.mjs`: пошук, обхід регіонів, парсинг списку та сторінки станції (cp1250).
- `sources/osm.mjs`: Overpass-запит для `amenity=fuel` у Словаччині.
- `geocode.mjs`: Nominatim (1 запит/с, кеш у `geocache.json`), геокодити лише нові адреси.
- `merge.mjs`: зіставлення станцій між джерелами, вибір свіжішої ціни.
- `index.mjs`: запуск усього, запис `stations.json`, `advice.json`, дописування `history.jsonl`; прапорець `--dry-run`.
- Тести (`node --test`) на фікстурах.

Вимоги: ідемпотентність, ретраї з паузою, м'яке падіння одного джерела (решта працює), логування кількості станцій і кількості цін, що змінилися.

## 7. PWA (`pwa/`)

Хостинг: GitHub Pages (HTTPS обовʼязково для геолокації).

Функції:

1. **Карта** (MapLibre GL або Leaflet + OSM-тайли): маркери станцій з ціною, кольором за рівнем (дешево/середньо/дорого відносно середньої), кластеризація.
2. **Фільтри**: вид пального, бренд, радіус, максимальний вік ціни.
3. **Список** «найдешевші поруч» за геолокацією користувача.
4. **Картка станції**: усі ціни, вік кожної, кнопка «Маршрут».
5. **Маршрут з економією** (розділ 8).
6. **Налаштування** (localStorage): пальне, витрата л/100 км, обʼєм заправки (л), радіус пошуку, максимальний обʼїзд (км), базова ціна (авто/ручна).
7. **PWA**: `manifest.webmanifest`, іконки, `apple-touch-icon`, service worker (кеш оболонки і останнього `stations.json` для офлайну), `display: standalone`, `viewport-fit=cover`, safe-area.
8. Мобільний UX: великі цілі для тапів, нижня панель, темна/світла тема.

## 8. Маршрут і розрахунок економії

Вхід: точки A, B, вид пального, витрата `c` (л/100 км), обʼєм заправки `L` (л), базова ціна `P0` (середня по маршруту/країні або ціна найближчої заправки до A).

Кроки:

1. Отримати маршрут A→B (OSRM або OpenRouteService), отримати polyline і довжину `D0`.
2. Відібрати станції в коридорі навколо маршруту (наприклад, буфер `X` км; можна `@turf/buffer` + `booleanPointInPolygon`, або швидка перевірка відстані до сегментів).
3. Для топ-N кандидатів за ціною (N≈10) порахувати маршрут A→станція→B, довжину `D1`. Обʼїзд: `detourKm = D1 − D0`.
4. Чиста вигода для кандидата `s`:

```
gain_s = (P0 − price_s) * L − detourKm * (c / 100) * price_s
```

5. Показати рейтинг за `gain_s`, позначити «варто / не варто» (`gain_s > 0`), вивести обʼїзд у км/хв та економію в EUR. Маршрут A→станція→B відкривається в Apple Maps / Google Maps через deep link.

Роутинг: `router.project-osrm.org` це демо-сервер, не для регулярного навантаження; для стабільності використати OpenRouteService (безкоштовний ключ, зберігати в конфігу PWA як публічний з обмеженням по домену) або запити зі скрипта з кешем. Запити обʼїзду робити лише для топ-N, а не для всіх станцій.

## 9. Віджет (`widget/`, Scriptable)

- Скрипт `FuelWidget.js` фетчить `data/advice.json` (і за потреби `stations.json`) з GitHub Pages.
- Бере координати через `Location.current()`, рахує відстань (haversine), показує 3 найдешевші станції в радіусі R для вибраного пального: назва, ціна, відстань, вік ціни.
- Тап по віджету: відкриває Apple Maps / Google Maps з вибраною станцією (URL scheme).
- Розміри small/medium; параметр віджета задає вид пального і радіус.
- iOS сам вирішує частоту оновлення (орієнтовно 15-30 хв); гарантованого фонового оновлення немає, це нормально.
- Інструкція встановлення у README: встановити Scriptable з App Store, вставити скрипт, додати віджет на домашній екран.

## 10. Конфігурація і секрети

Змінні (Actions → Variables / `.env.example`):

- `CITIES` (`all` або `kosice,bratislava,…` — міста з налаштувань PWA), `DAY_WINDOW`
- `REQUEST_DELAY_MS`, `USER_AGENT`
- `NOMINATIM_EMAIL`
- `ORS_API_KEY` (лише якщо використовуємо ORS)
- `NOTIFY_*` та `TELEGRAM_*`: опційно, якщо додати сповіщення про дешеву ціну (як у privat_currency)

## 11. GitHub Actions

- `collect.yml`: cron раз на добу (`15 5 * * *` UTC) + `workflow_dispatch`. Кроки: checkout → setup-node → `node engine/index.mjs` → комміт змін у `data/` (потрібні права Read and write) → деплой Pages.
- `pages.yml` (або та сама job): збірка/копіювання `pwa/` і `data/` у артефакт Pages.
- `test.yml`: `node --test` на PR.

## 12. Етапи

1. **Збір даних**: парсер benzin.sk на фікстурах, `stations.json` для одного краю (Košický), тести.
2. **Координати**: геокодинг + кеш, зіставлення з OSM.
3. **PWA v1**: карта, ціни на маркерах, фільтри, геолокація, встановлення на головний екран.
4. **Віджет**: Scriptable, `advice.json`.
5. **Маршрут з економією**: коридор, обʼїзд, рейтинг за `gain`.
6. **Усі краї + додаткові джерела**, історія цін і графіки, сповіщення (опційно).

## 13. Критерії готовності (MVP)

- `node engine/index.mjs --dry-run` працює локально і створює валідний `stations.json` для Košického краю.
- PWA відкривається на iPhone з головного екрана, показує станції поруч із цінами й віком ціни.
- Віджет показує 3 найдешевші станції в радіусі.
- Для заданих A і B застосунок показує принаймні 3 кандидати із чистою вигодою й обʼїздом.
- Тести парсера проходять на збережених фікстурах (cp1250).
